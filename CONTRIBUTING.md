Thank you for contributing to the **INSA Helpdesk System**!

Please review our [README.md](./README.md) for full details on:
- Branching strategy (`main`, `dev`, `feature/*`, `fix/*`)
- Step-by-step Git workflow (pulling, branching, committing, pushing, PR creation)
- **DO's and DON'Ts** for collaborators
- Conventional Commit message formats
- Local backend and frontend setup

---

## ⚡ Quick Checklist for Pull Requests

Before submitting a Pull Request, please ensure:
1. [ ] You branched off the latest `dev` (or `main`) branch.
2. [ ] Your code compiles and runs locally without errors.
3. [ ] No sensitive credentials, keys, or `.env` files are included in your commit.
4. [ ] Your branch name follows `feature/name` or `fix/name`.
5. [ ] Your commit messages follow Conventional Commits (e.g., `feat(frontend): ...`).
6. [ ] You have requested a review from at least one peer.
